v21.8.6
  - Fix all radio channels except Stingray failing with a 403 error. minvbr
    and maxvbr are video bitrate bounds, but were being filled from the audio
    bitrate on radio channels, so audio-only profiles asked the CDN for video
    that does not exist
  - Fix radio channels being signed with an empty signature: their
    publishing points only advertise a "radio" player config, never a "live"
    one, which was the only type being read
  - Update the service provider list to match EON's own: SBB, Telemach,
    Telemach HR, Telemach SI, Vivacom, Nova. NetTV Plus and EON Hrvatska no
    longer exist as brands
  - Fix providers resolving to the wrong CDN after the broker changed its
    brand list: entries with no identifier of their own fell back to
    whatever brand sat at the same position, which no longer matched.
    Brands are now matched by their own identifier, and an unknown one
    falls back to the CDN the broker marks as default
  - Fix the EPG failing with "invalid_input" when Kodi requests a range
    reaching past EON's 7-day archive; the request is now clamped to what
    the archive actually holds
  - Add an optional custom User-Agent setting
  - Fix a shutdown race in the seek proxy that could corrupt memory: the
    listening socket was closed from one thread while another was still
    selecting on it
  - Add a connection timeout to all HTTP requests, which previously had none
  - Add Serbian, Croatian, Bosnian, Slovenian, Macedonian and Greek translations
  - Small organisational and cosmetic fixes

  NOTE: the provider list order has changed. If you had Vivacom selected, or
  were using NetTV Plus as a workaround to log in to a Vivacom account, open
  the add-on settings and select your provider again. Vivacom accounts now
  work with Vivacom selected. EON Hrvatska has been replaced by Telemach HR.

v21.8.5
  - Fix being unable to return to live TV from the guide: while a replay show
    was playing, selecting the channel's currently airing programme did
    nothing at all. Replay is opened as an EPG-tag playback session again
    rather than claiming the channel session, which is what made Kodi treat
    the channel as already playing live and skip the re-tune. Trade-off: the
    displayed title stays pinned to the selected show if playback continues
    past its scheduled end (progress and seeking stay correct)
  - Fix "playback failed" when two stream opens overlap. The local seek proxy
    was torn down and relistened on a fresh port for every new stream, which
    left the open already in flight pointing at a dead port. It now keeps one
    port for the add-on's lifetime and tracks each stream as its own session,
    so concurrent opens no longer invalidate each other. Overlap is routine:
    Kodi asks for an EPG tag's stream properties twice per playback, and its
    "play next programme automatically" can fire at the same moment the user
    picks something else in the guide
  - Declare inputstream.ffmpegdirect as a dependency again so Kodi installs
    it automatically; it is the inputstream the add-on's own documentation
    tells users to select, but the import was dropped in 2023
